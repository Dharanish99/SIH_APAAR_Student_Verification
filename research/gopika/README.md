## Questions to answer
1. Who enters, checks, approves and submits admission data, and which systems do they use?
2. Which fields are repeatedly entered, and which corrections take the most effort?
3. How do withdrawals, transfers, course changes and identity mismatches move through the current workflow?
4. What do admission staff, nodal officers, students, placement staff and regulators each need?
5. Which relevant functions already exist in an ERP, APAAR/ABC, NAD or reporting portals?
6. What would make institutions adopt our platform, and what would increase their workload?

## Suggested work sequence
1. Read the shared problem brief and map the current admission-to-reporting process.
2. Seek two short staff conversations and two or three student conversations if available. Start at SECE; capture roles and dates, not personal records.
3. Ask for a walkthrough of a recent submission and a blank or anonymised input template.
4. Compare 3–5 existing systems using documented capabilities. Mark unavailable information as unknown.
5. Prioritise five pain points by evidence, frequency, impact and confidence.
